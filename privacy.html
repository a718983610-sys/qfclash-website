三、我们处理的数据

（一）仅保存在你的设备本地的数据

下列数据仅保存在你的设备本地（应用私有目录，用户主动使用云端备份功能时除外），维护者不主动收集、不上传、不出售：

  3. 软件设置；
  4. 诊断日志（仅在你主动导出并发送时，维护者才会收到，并仅用于处理你反馈的问题）。

你可在软件内清空配置与统计。卸载后，应用私有目录中的数据通常会随卸载删除；你主动导出并保存在其他位置的文件可能继续存在，请在卸载前自行检查并删除不再需要的文件。

（二）使用账号服务时在服务器侧处理的数据

你注册、登录并使用账号功能时，维护者会在服务器侧处理下列数据：

  1. 账号资料：你自设的账户 ID、电子邮箱地址、经不可逆加密处理的密码、账号状态与注册时间。
  2. 个人资料：你设置的昵称与头像。昵称与头像会在本软件、论坛与好友场景中公开显示；账户 ID 仅向你的好友可见；电子邮箱地址不对外显示，仅你本人在「我的」中可见。
  3. 登录与设备信息：登录设备的设备名称、平台类型（安卓 / Windows）、最近活跃时间、登录地区，以及设备标识哈希（构成与用途见第四节）。
  4. 会话与安全记录：登录令牌的签发与使用记录、验证码的发送与核验记录（含查看兑换码时的核验记录）、登录与安全操作日志、封禁与申诉记录，以及登录与申诉等安全日志中的 IP 地址。该等 IP 地址仅用于安全风控，并在实现安全风控、申诉复核与争议处理目的所必需的期限内保存，期限届满后删除或匿名化处理；法律法规另有要求的除外。为防范批量注册与注册、注销循环滥用，系统对注册与注销完成事件，按设备标识哈希、网络地址与邮箱维度作短期记账，用于执行注册冻结规则；该记账记录保存三十天后删除。你通过找回申诉找回账号时，你填写的曾用密码仅以不可逆方式与现有密码作比对，系统只记录命中的个数，不保存你填写的明文；你自述的曾用设备机型、登录地点及系统据此生成的核对结果，将用于申诉审核与安全审计，并随账号注销一并删除。
  5. 积分与兑换记录：计时心跳记录、积分流水（每笔增减的时间、事由与余额）、兑换订单与审核记录。兑换美元奖励时，还包括你填写的发放信息：USDT（TRC20）收款地址，或你选择礼品卡时填写的接收邮箱，以及发放状态与发放备注；该等信息仅用于审核与发放，仅你本人与维护者可见。兑换时，系统还会处理时区等兑换地域判定信号；该等信号仅用于判定兑换是否可用，并随兑换审计记录保存，保存期限为实现判定与审计目的所必需的期限。
  6. 你主动提交的内容：意见反馈内容与你自愿填写的联系方式（提交时系统会自动附带应用版本、平台信息，登录状态下附带账号信息，以便定位问题）；你在论坛发布的帖子、回复，以及与之相关的审核、举报与处置记录。

  8. 通行密钥公钥凭证：你创建通行密钥后，服务器保存其公钥凭证、凭证名称、创建时间、最近使用时间与签名计数。通行密钥的私钥始终保存在你的设备或系统通行密钥服务中，不会上传至服务器。

  12. 设置备份密文：你主动使用设置云备份功能时，服务器保存经加密的设置备份密文，维护者无法解密。设置云备份的同步范围仅包括可移植设置，不包括平台专属设置、本机路径、窗口状态与本地凭据类设置。
  13. 客服会话数据：你使用智能客服或转人工客服功能时，服务器保存你与客服的会话内容，用于答复咨询与处理问题。客服会话不采用端到端加密，会话内容对服务方可见，与本条第 7 项好友聊天的端到端加密严格区分，请勿在客服会话中发送密码、验证码等敏感信息。智能客服为自动回复系统，不冒充真人；转人工后的回复由人工客服作出。客服会话数据随账号注销一并删除。
  14. 论坛互动与浏览记录：你在论坛中进行点赞、分享、浏览时，系统将记录相应的互动信息。点赞与分享的次数将公开展示于相应帖子；为防范刷量与虚假互动，系统同时保存点赞来源的设备标识哈希与网络地址的哈希摘要，仅用于互动真实性核查。你在论坛中的逐帖浏览记录，仅用于生成你本人的「数据分析」页面（包括你常浏览的内容主题、你发布与评论的数据统计），并为你推荐可能感兴趣的帖子与营地（主题社区）；浏览记录与数据分析结果仅你本人可见，不向其他用户展示。营地的加入与关注关系将保存在服务器，用于呈现你加入的营地内容。你创建的营地的名称、简介与创建者身份（昵称与头像）为公开信息，将在营地页面公开展示。你申请帖子点赞奖励时，系统将保存你的申请记录与审核结果，用于奖励审核与发放。

聊天会话删除的同步范围：你在软件内删除聊天会话时，删除的是你本人的聊天密文归档与你本人设备上的副本。你本人在其他设备上的副本，将在该设备联网并同步后删除。对方持有的聊天记录副本不受该删除操作影响。

使用访客模式无需注册账号。为核算访客每日可用额度，服务器会处理设备标识哈希及与额度核算有关的日期、已用时长记录。

（三）联网时第三方可能处理的连接信息

  1. 检查更新：你主动检查更新时，软件会向官方仓库或相关发布服务发送请求，该等服务提供方可能按其适用的隐私规则处理你的 IP 地址、请求时间、客户端版本等连接信息。
  2. 导入或更新订阅：软件会向你指定的订阅地址发送请求，相应服务商及网络服务提供方可能获取该请求所需的连接信息，其处理行为由其自身规则约束，维护者无法控制。
  3. 账号请求：登录、注册与验证请求由软件直接向账号服务器发出，不经代理节点转发。
  4. 邮件发送：注册、找回密码、更换邮箱、异常验证、兑换发放通知等邮件，经邮件发送服务发出，该服务提供方会处理收件邮箱地址与发送所必需的信息。
  5. 兑换地区判定：为执行福利兑换的地区规则，系统会在你提交兑换时，根据连接来源判断所在的国家或地区，并处理时区等兑换地域判定信号；该等判定与信号仅用于决定兑换是否可用及审计，不影响积分累计。

（四）网页版

关于网页版：网页版与客户端使用相同的账号体系与端对端加密协议，你的聊天内容不会以明文形式经过服务器。但受浏览器运行环境所限，网页版对保存在本设备浏览器中的身份密钥与会话信息的保护强度低于客户端应用。网页版的身份密钥仅保存在浏览器内存中，页面关闭后即清除；退出登录时，本设备的会话令牌将被清理。请勿在公共或不受信任的设备上使用网页版；确需使用的，请在使用完毕后退出登录。

四、设备标识哈希

设备标识哈希由设备安装标识与硬件特征组合计算而成。服务器只保存哈希值，不保存可直接识别设备的原始硬件特征。

设备标识哈希仅用于：验证身份与保障账号安全；防范批量注册、刷取积分、伪造计时等作弊与滥用行为；核算访客每日额度；执行注册限制、产分限制与设备封禁；支持安全中心的设备展示与远程下线。

设备标识哈希不用于广告投放、行为追踪或用户画像，不会被出售或出租。

五、数据的使用目的

维护者仅在下列目的范围内使用第三节所列数据，不作无关使用：

  1. 创建与维持账号，验证身份，保障账号安全；
  2. 记录与结算积分，处理兑换、审核与发放；
  3. 提供好友与端到端加密聊天服务（仅中继密文与分发公钥包）；
  4. 处理意见反馈，运营论坛并实施内容审核与管理；
  5. 防范作弊与滥用，执行封禁、禁言等处置并处理申诉；
  6. 完成你主动发起的检查更新、订阅导入或更新、邮件发送等请求；
  7. 生成你本人的论坛数据分析与内容推荐（数据来源与范围见第三节关于论坛互动与浏览记录的说明）。

将数据用于上述以外的新目的时，维护者将依法另行告知，并在需要时取得你的同意。

六、数据的存储与服务商

账号数据存储于维护者运营的账号服务器，当前采用 Cloudflare 提供的云服务（Workers 与 D1 数据库）。邮件经邮件发送服务（当前为 Resend）发送。官方网站与网页版当前由 GitHub Pages 托管。维护者接收运营通知的邮件中可能包含与待处理事项相关的账号标识，仅用于运营处理。

存储地点或主要服务商发生重大变更的，维护者将通过修订本说明、协议修订或官方公告告知。

七、保存期限与删除

  1. 本地数据保存在你的设备中，直至你自行删除、清空或卸载处理（见第三节第（一）款）。
  2. 账号数据在账号存续且提供服务所必需的期间内保存。你在安全中心申请注销后进入 7 天冷静期，冷静期内登录即可撤销；冷静期届满后，维护者将删除你的服务器账号数据，包括订阅备份密文、聊天密文归档及包裹后的保险库密钥、设置备份密文、聊天消息的中继密文、通行密钥公钥凭证与加密聊天密钥备份，删除后不可恢复；同时账号积分清零，未使用的兑换码作废。
  3. 法律法规要求留存的个别日志记录，不随注销立即删除，将在法定期限届满后删除。
  4. 反馈、论坛、审核与安全审计记录，在实现问题处理、内容管理、安全审计、申诉复核与争议处理目的所必需的期限内保存，目的实现后删除或匿名化处理；依法必须留存的除外。
  5. 第三方服务提供方处理的数据，其保存期限由其自身规则确定。

八、我们不做的事

  1. 本软件不集成任何第三方广告、统计或行为追踪组件。
  2. 维护者不出售、不出租你的账号数据，不将其用于与本软件无关的营销。
  3. 软件内仅有 QFClash 自身的介绍与宣传内容，出现在「关于」页等固定位置，不弹窗、不影响操作。

九、你的权利与行使方式

你可以通过安全中心查看与管理你的账号信息与登录设备，包括修改密码、更换绑定邮箱、查看并远程下线设备、申请注销账号；可以在积分页面查看余额与逐笔流水。

你有权依法向维护者提出查询、更正、删除账号数据的请求，或咨询数据处理事项。可通过安全中心自助办理，或通过第二节邮箱联系；维护者将在核实身份后处理。依法或因安全、争议处理需要暂不能满足的，维护者将说明原因。绑定邮箱无法使用时，可通过邮箱申请人工核验。

未成年人请在监护人陪同下阅读本说明与《QFClash 用户使用协议》，并由监护人决定是否同意。监护人认为未成年人未经同意提供了数据的，可通过第二节邮箱联系维护者，核实后依法处理。

3. Data We Process

(1) Data stored only locally on your device

The following data is stored only on your device (in the app's private directory, except when you actively use a cloud backup feature). The maintainer does not actively collect, upload, or sell it:

  1. Subscription links and subscription configurations;
  2. Node selections, traffic statistics, and speed-test records;
  3. Software settings;
  4. Diagnostic logs (received by the maintainer only when you actively export and send them, and used only to address the issue you reported).

You may clear configurations and statistics within the software. After uninstallation, data in the app's private directory is normally deleted along with the app; files you exported and saved elsewhere may continue to exist, so please check and delete any files you no longer need before uninstalling.

(2) Data processed on the server when you use account services

When you register, sign in, and use account features, the maintainer processes the following data on the server:

  1. Account details: your self-chosen account ID, email address, password processed with irreversible encryption, account status, and registration time.
  2. Profile: the nickname and avatar you set. Your nickname and avatar are publicly displayed in the software, the forum, and friend contexts; your account ID is visible only to your friends; your email address is not displayed to others and is visible only to you under "My".
  3. Sign-in and device information: the name of the signing-in device, platform type (Android / Windows), most recent activity time, sign-in region, and the device identifier hash (see Section 4 for its composition and purposes).
  4. Session and security records: records of sign-in token issuance and use, verification code sending and verification records (including verification records when viewing redemption codes), sign-in and security operation logs, ban and appeal records, and the IP addresses in security logs such as sign-in and appeal logs. Such IP addresses are used only for security risk control and are retained for the period necessary to achieve the purposes of security risk control, appeal review, and dispute handling, after which they are deleted or anonymized, except where laws and regulations provide otherwise. To guard against bulk registration and register/delete cycling abuse, the system keeps short-term accounts of registration and account-deletion completion events by device identifier hash, network address, and email, in order to enforce the registration freeze rules; these accounting records are deleted after thirty days. When you recover your account through a recovery appeal, any former passwords you provide are compared against your current password only in irreversible form; the system records only the number of matches and does not store the plaintext you entered. The former device models and sign-in locations you state, and the verification results the system generates from them, are used for appeal review and security auditing, and are deleted together with account deletion.
  5. Points and redemption records: usage heartbeat records, points ledger entries (the time, reason, and balance of each change), and redemption orders and review records. When you redeem a USD reward, this also includes the payout information you provide: a USDT (TRC20) receiving address, or the receiving email you provide if you choose a gift card, together with payout status and payout remarks; this information is used only for review and payout, and is visible only to you and the maintainer. When you redeem, the system also processes redemption-region determination signals such as your time zone; such signals are used only to determine whether redemption is available, and are retained together with the redemption audit records for the period necessary to achieve the purposes of determination and auditing.
  6. Content you submit: feedback content and any contact details you voluntarily provide (the system automatically attaches the app version and platform information, and account information when you are signed in, to help locate the issue); posts and replies you publish on the forum, and related moderation, report, and enforcement records.
  7. Friend and encrypted chat data: friend relationships and friend request records; chat encryption public key bundles (identity public key, signed pre-key, and one-time pre-keys); ciphertext of chat messages; and chat key backups encrypted with a key derived from your account password. Chat uses end-to-end encryption: the server stores and relays only ciphertext and public key material and cannot read message plaintext; the key material of encrypted backups is encrypted with a key derived from the password you set, and the maintainer cannot decrypt it. The relay ciphertext of chat messages is retained while the account exists and is deleted together with account deletion. Chat attachments: you can send images and files in friend chats. Attachments are encrypted on your device before sending; the server stores and relays only ciphertext and cannot read attachment contents. Limits apply to the size of a single attachment and to the total attachment capacity per account (as indicated in the software). An attachment lives as long as the message that references it; after the message is deleted, the attachment is cleared within a short period; when the account is deleted, the ciphertext of attachments related to you is deleted together.
  8. Passkey public key credentials: after you create a passkey, the server stores its public key credential, credential name, creation time, most recent use time, and signature counter. The private key of a passkey always remains on your device or in your system's passkey service and is never uploaded to the server.
  9. Google sign-in information: when you choose Google sign-in, the maintainer reads your email address within the scope of the information returned by Google, for the purpose of verifying your email, and stores the unique identifier of your Google account in order to recognize the same account. After your email has been verified through Google sign-in, you must still set an account ID and a sign-in password to complete registration. Signing in with Google and registering with email using the same email address are treated as the same account.
  10. Subscription backup ciphertext: when you actively use the cloud backup feature, the server stores the subscription backup ciphertext you upload. This backup uses end-to-end encryption; the server stores only the ciphertext, and the maintainer cannot decrypt it; forgetting your account password will make the subscription backup unrecoverable.
  11. Chat ciphertext archive (history vault): when you actively use the chat history cloud sync feature, the server stores the archive entries encrypted end-to-end, and the vault key wrapped with a key derived from your account password; the maintainer cannot decrypt the archive contents. The archive limit per account is 20,000 entries and no more than 64 MB. You may clear the chat ciphertext archive within the software; when the cooling-off period for account deletion expires, the chat ciphertext archive and the wrapped vault key will be deleted together.
  12. Settings backup ciphertext: when you actively use the settings cloud backup feature, the server stores the settings backup ciphertext in encrypted form, and the maintainer cannot decrypt it. The sync scope of settings cloud backup includes portable settings only, and does not include platform-specific settings, local paths, window state, or local credential-type settings.
  13. Customer service conversation data: when you use the smart customer service or transfer-to-human customer service features, the server stores the content of your conversations with customer service, for use in answering inquiries and handling issues. Customer service conversations do not use end-to-end encryption, and the conversation content is visible to the service provider; this is strictly distinct from the end-to-end encrypted friend chat in item 7 of this paragraph, so please do not send passwords, verification codes, or other sensitive information in customer service conversations. The smart customer service is an automatic reply system and does not impersonate a human; replies after transfer to a human are made by human customer service. Customer service conversation data is deleted together with account deletion.
  14. Forum interaction and browsing records: when you like, share, or browse in the forum, the system records the corresponding interaction information. Like and share counts are publicly displayed on the corresponding posts; to guard against fake engagement, the system also stores the device identifier hash of the like source and a hash digest of the network address, used only to verify the authenticity of interactions. Your per-post browsing records in the forum are used only to generate your own "Data Analysis" page (including the content topics you browse most, and statistics of your posts and comments) and to recommend posts and camps (topic communities) that may interest you; browsing records and data analysis results are visible only to you and are not shown to other users. Camp membership and following relationships are stored on the server to present the camp content you have joined. The name, introduction, and creator identity (nickname and avatar) of a camp you create are public information and will be publicly displayed on the camp page. When you apply for a post like reward, the system stores your application record and review result for reward review and granting.
  15. External highlights: the forum has an external highlights section displaying the titles, summaries, and original links of public content from third-party platforms, with the source platform noted; such content is displayed after review by the maintainer. Clicking a link takes you to the third-party platform, whose handling of its services and content is governed by its own rules and cannot be controlled by the maintainer. Your browsing behavior in the external highlights section is handled under the forum browsing record terms of this Notice.

Scope of sync for chat conversation deletion: when you delete a chat conversation within the software, what is deleted is your own chat ciphertext archive and the copies on your own device. Copies on your other devices will be deleted after those devices connect to the network and sync. Copies of chat records held by the other party are not affected by that deletion.

Guest mode requires no account registration. To account for the daily guest allowance, the server processes the device identifier hash and records of the date and used duration relevant to allowance accounting.

(3) Connection information third parties may process when you connect

  1. Update checks: when you actively check for updates, the software sends requests to the official repository or related release services; those providers may process connection information such as your IP address, request time, and client version under their own applicable privacy rules.
  2. Subscription import or update: the software sends requests to the subscription address you specify; the relevant providers and network service providers may obtain the connection information needed for the request, and their processing is governed by their own rules, which the maintainer cannot control.
  3. Account requests: sign-in, registration, and verification requests are sent by the software directly to the account server and are not forwarded through proxy nodes.
  4. Email delivery: emails for registration, password recovery, email change, exceptional verification, and redemption payout notifications are sent through an email delivery service, which processes the recipient email address and the information necessary for delivery.
  5. Redemption region determination: to enforce the region rules for benefit redemptions, when you submit a redemption the system determines your country or region from the connection source, and processes redemption-region determination signals such as your time zone; such determinations and signals are used only to decide whether redemption is available and for auditing, and do not affect points accumulation.

(4) Web version

About the web version: the web version uses the same account system and end-to-end encryption protocol as the client apps, and your chat content never passes through the server in plaintext. However, due to the limits of the browser runtime environment, the web version protects the identity keys and session information stored in this device's browser less strongly than the client apps. The web version's identity keys are kept only in browser memory and are cleared when the page is closed; when you sign out, this device's session tokens are cleared. Please do not use the web version on public or untrusted devices; if you must, sign out after use.

4. Device Identifier Hash

The device identifier hash is computed from a combination of the device installation identifier and hardware characteristics. The server stores only the hash value; it does not store the raw hardware characteristics that could directly identify a device.

The device identifier hash is used only to: verify identity and safeguard account security; prevent abuse such as bulk registration, points farming, and forged usage timing; account for the daily guest allowance; enforce registration limits, points-earning limits, and device bans; and support device display and remote sign-out in the Security Center.

The device identifier hash is not used for advertising, behavioral tracking, or user profiling, and will not be sold or rented.
